# Поиск автозапчастей и аналогов — Favorit-Parts

Тестовое задание: приложение на React с двухэтапным подбором номенклатуры по Web-сервису
«Проценка» (`api.favorit-parts.ru/hs/hsprice/`).

1. Вводите артикул — приложение показывает производителей, которые выпускают эту деталь.
2. Выбираете производителя — получаете его деталь и аналоги с ценами и остатками.

## Что сделано

- **Этап 1.** Поле артикула с задержкой 500 мс: запрос уходит, когда перестали печатать.
  В ответе — список производителей без дублей и пустых записей.
- **Этап 2.** Клик по производителю отправляет второй запрос с `brand` и `analogues=on`,
  результат — таблица: производитель, артикул, наименование, остаток, цена. Выбранная деталь
  отделена от аналогов, аналоги отсортированы: сначала то, что есть на складе, внутри — по цене.
- **Цена считается по складам.** В документации `goods.price` помечен «не использовать, цену
  брать из конкретного склада». Поэтому берётся минимальная цена среди складов, где есть остаток;
  если остатка нет нигде — минимальная по складам, а строка помечается «нет в наличии»;
  когда подходящих складов несколько, в таблице «от N ₽».
- **Состояния.** `loading / success / error` на каждый этап: лоадеры, подсказки на пустом экране
  и понятные сообщения об ошибках. Разобраны все ответы API: `Empty key!`, `Invalid key client!`,
  `Request quota exceeded!`, HTTP-сбой, отсутствие сети.
- **Отмена запросов.** Если быстро поменять артикул или бренд, устаревший запрос обрывается
  через `AbortController` — поздний ответ не перезапишет свежий, а отмена не показывается ошибкой.
- **Мелочи, которые заметны в работе.** Пока грузится новый бренд, старая таблица остаётся
  под полупрозрачным лоадером и страница не прыгает. Пустой ответ API (массив с одной пустой
  структурой) распознаётся и превращается в «ничего не найдено».

## Технологии

| Технология | Зачем |
|---|---|
| React 18, hooks | интерфейс, без TypeScript |
| Redux Toolkit, react-redux | два слайса: `brands` (этап 1) и `analogues` (этап 2) |
| axios | запросы к API |
| Bootstrap 5 + SCSS | сетка, таблица, кнопки; тема переопределена переменными |
| Vite 5 | dev-сервер, сборка, прокси к API |
| Vitest | юнит-тесты нормализации и экшенов |
| ESLint | линт без ошибок |

Адаптив: две колонки на десктопе и стек на мобильном, таблица прокручивается горизонтально,
артикулы и цены не переносятся.

## Как запустить

Нужен Node.js 18 или новее.

```bash
npm install
npm run dev     # http://localhost:5173
```

Открыть http://localhost:5173 и ввести артикул, например `01089` (стеклоподъёмники),
`0189` (свечи) или `7160500039S` (опора). Появится список производителей — клик по любому
загрузит деталь и аналоги.

Ключ покупателя уже подставлен — тестовый, из примеров документации. Свой можно положить
в `.env` строкой `VITE_API_KEY=…`, он важнее значения по умолчанию.

Остальные команды:

```bash
npm run build     # production-сборка в dist/
npm run preview   # посмотреть собранное
npm test          # vitest, 10 тестов
npm run lint      # eslint
```

## Структура

```
src/
  api/http.js                 экземпляр axios: базовый адрес и ключ
  redux/
    store.js                  configureStore
    initialState.js           начальные состояния обоих этапов
    slices/                   brandsSlice, analoguesSlice
    actions/                  brandsAction, analoguesAction (+ тесты)
  hooks/useDebounce.js        пауза, пока печатают
  utils/
    normalizeBrands.js        производители: без пустых и дублей
    normalizeOffers.js        строки таблицы: цена со складов, остаток, аналоги
  Components/
    features/PartSearch       этап 1: поле артикула и список брендов
    features/BrandList        список производителей
    features/Analogues        этап 2: состояния и таблица
    features/AnaloguesTable   таблица «деталь + аналоги»
    UI/                       SearchInput, Preloader, EmptyState, ErrorMessage
    List/ListItems.jsx        общий рендер списка
  styles/main.scss            Bootstrap с переменными темы
```
